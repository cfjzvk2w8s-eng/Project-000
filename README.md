## GitHub Terminology

Plain-English translations of common GitHub terms used in this project:

- **Branch** (noun) — An independent line of development in the repository, allowing changes to be made without affecting other branches until merged.
- **Commit** (noun) — A saved snapshot of your changes, with a message describing what changed.
- **Git** (proper noun) — The version control system that GitHub is built on top of, used to track and manage changes to files over time.
- **Remote** (noun) — A version of the repository hosted elsewhere (e.g., on GitHub) that your local copy can send changes to or fetch changes from.
- **Remote branch** (noun) — A branch that lives on the remote (GitHub) rather than only on your local machine.
- **Main** (noun) — The primary branch of the repository, usually representing the latest stable/released code.
- **Base** (noun) — The starting point a set of changes is compared against or built on top of.
- **Base branch** (noun) — The branch that a pull request's changes will be merged into (often `main`).
- **Pull** (verb) — To download and merge changes from a remote branch into your local branch.
- **Pull request (PR)** (noun) — A request to merge changes from one branch into another, which others can review and discuss before it's merged.
- **Request** (noun) — An ask directed at repository maintainers or collaborators to take an action, most commonly to review and merge a pull request.
